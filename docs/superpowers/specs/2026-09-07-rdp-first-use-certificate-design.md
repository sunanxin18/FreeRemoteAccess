# RDP 首次证书记录与变化阻断

用户于 2026-09-07 明确指定：首次连接只显示并保存证书，不因首次身份未知失败；
后续指纹变化停止自动连接并提醒。此规则取代旧 RDP 设计中“未知证书需人工确认”
以及“名称不匹配不可覆盖”的部分，仅作用于 Windows RDP。

## 行为

- 首次连接采用首次使用信任（TOFU）。自签名、CA 不受信任、主机名不匹配或
  缺少 IP SAN 不阻止这条路径。证书格式、有效期、RDP/服务器用途及 TLS 握手
  签名仍必须有效。
- 无凭据预检取得服务器证书身份后，应用先按协议、目标主机和端口持久化
  SHA-256 指纹，再允许实际认证连接。证书主题、签发者与指纹在连接状态详情
  中显示；持久化身份记录是指纹，不包含私钥或登录凭据。
- 已记录目标必须匹配原指纹。变化时保留原记录，停止自动连接，显示中文变化
  提示，不提供自动覆盖、静默重试或自动重置信任。
- 存储读取、写入失败或记录损坏时停止连接；否则无法履行后续指纹检查保证。
- 即使系统信任链有效，首次连接也必须记录指纹。预检与后续真实 TLS 连接
  必须返回同一张证书；二者间变化会在发送账号密码前停止。

## 分层与存储

复用协议中立的 `ServerIdentityChallenge` / `ResolveServerIdentity` 事件与命令。
RDP 每次发布证书身份及 unknown/matched/mismatch，应用层核对当前 session、协议、
endpoint 和持久化记录，只在保存或匹配成功后排队继续命令；桌面 shell 转发命令。
取消、旧 session 和重复事件不得发出额外继续命令。其他协议维持已有行为。

Windows 使用既有当前用户 DPAPI 指纹存储，保持 `FRDPIN01` 格式。首次文件发布
必须原子且不覆盖已有目标文件，防止并发首次连接替换旧指纹。macOS 无 GUI 验证
探针的目录存储仅用于有界测试，不能当作 macOS 产品平台存储的交付证据。

## 呈现与范围

复用现有标题栏连接状态图标的悬停/键盘聚焦详情与无障碍名称，首次不弹出需要
决定的模态框，不占用远程内容区域。变化错误持续显示至用户返回连接页，不能由
随后正常关闭事件覆盖。没有新增图标、按钮族或原生窗口几何。

核对的官方组件依据为 [Material 3 Tooltips](https://m3.material.io/components/tooltips/overview)
及 [Apple Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)。
首次仅为身份信息，不要求决策；变化时用现有错误页说明具体问题。使用现有标题栏
详情是遵守本项目远程内容边界的呈现选择，不改变窗口原生控制。

验证覆盖首次保存、相同指纹、变化拒绝、并发不覆盖、存储失败、旧 session、取消、
错误保留、证书名称兼容和预检后证书变化。真实目标测试另列记录，协议登录与解码
结果不升级为 Windows GUI、键鼠、音频或完整远程桌面验收。
