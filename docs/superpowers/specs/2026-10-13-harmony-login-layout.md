# HarmonyOS 手机登录页布局修正

2026-10-13，用户反馈手机登录信息无法一屏完整显示，视觉层级松散。本改动仅修正 ArkUI 登录表单布局、最近连接入口并移除登录页开发验证工具，复用既有原生组件、平台字体和明暗色令牌。

用户随后明确要求“请把开发验证去掉”，覆盖此前任务说明保留调试入口的要求。因此从登录页完全删除开发验证按钮、面板、专用状态与返回分支，不提供折叠菜单等替代入口。底层离线图形/test 设施保持原状，不作为登录产品 UI 的一部分。此前包含该入口的截图属于中间版本；主代理必须重新构建、签名、安装并验收最终无入口版本。

2026-10-14补充：debug HAP也不得通过启动参数打开离线图形验证页。删除ArkUI的POC页面分支、状态轮询以及EntryAbility的`frd_graphics_poc` Want处理；独立原生测试设施保留。验收覆盖手机与PC的普通启动、旧参数冷启动和旧参数运行中启动，均保持正常登录页。

## 设计依据与目标

遵循官方 [Material 3 文本字段指南](https://m3.material.io/components/text-fields/guidelines)的持久标签与字段分组原则、[Material 3 自适应布局](https://m3.material.io/foundations/layout/canonical-examples/overview)的紧凑宽度适配，以及 [Apple HIG 布局](https://developer.apple.com/design/human-interface-guidelines/layout)和[文本字段](https://developer.apple.com/design/human-interface-guidelines/text-fields)的安全区、平台输入与标签关联原则。主代理在实施前完成相关官方指导审阅。

视觉方向为克制的原生工具表单：中文任务标题优先，产品名作为较小的次要标识；字段成组，主要“连接”动作清晰，登录产品界面只包含连接任务所需信息。无审美例外，也不引入新图标或字体。

正常手机竖屏、键盘收起、默认字体下，在已观察的 359vp 宽、722vp 高可用区域中显示目标系统、主机地址、端口、用户名、密码、安全保存选项和连接按钮。无最近记录的基础布局目标约 650vp；最近记录数目不增加页面高度。不能通过隐藏错误、缩小触摸区域、取消字段或取消滚动达成目标。

## 布局与交互

- 宽度小于 600vp 或高度小于 500vp 进入紧凑间距：外侧 16vp、上下 16vp；较宽桌面上下与外侧 24vp。表单继续水平居中，最大宽度 440vp，保留平台原生窗口控件与安全区。
- “连接远程桌面”紧凑布局 24fp、较宽布局 28fp；产品名 12fp；标题独占完整表单宽度。
- 字段标签 14fp，字段内标签与输入框间距 6vp，字段组间距 12vp。输入文字 16fp，目标系统与端口同排；目标系统分配剩余空间，端口宽 96vp。主机地址与两项凭据保持整行。
- 输入框、选择器和按钮最小高度均为 48vp；只约束最小高度，较大字体可使内容自然扩展。页面一直保留 Scroll，键盘仍使用 `KeyboardAvoidMode.RESIZE`。横屏、较小窗口、大字和更多错误信息允许安全滚动。
- 最近连接改为单个原生 Select，菜单列出地址、端口与用户名，菜单由原生组件限制高度并可滚动。选择继续沿既有 native profile action 和 snapshot 确认路径恢复字段，并以 `passwordEpoch` 重建密码输入。
- 安全保存复选框视觉为 24vp，文字和视觉状态位于一个最小 48vp 高的原生按钮内。整行只有一个操作回调；视觉复选框不独立接收命中或键盘焦点。整行提供 checkbox 可访问角色、名称及 checked 状态，原生按钮承担指针和键盘激活。
- loading、安全存储载入提示、协议不可用说明、表单错误、操作 notice 与 bridge notice 仍在表单中持续显示；字段错误使用现有 showError 路径。新增显示既有 target/protocol/profile 错误字段。

## 语义边界

保持目标系统更换时默认端口、FormEdit、appAction 编号、profile 选择确认、passwordEpoch、安全存储读写与授权语义。密码只由现有 native.editPassword 收到，未增加 ArkUI 密码状态、日志、快照或普通文件存储。密码 onChange、输入法合成批次、Enter 按键去重和 onSubmit 的回调正文保持原样；连接按钮继续调用相同 submit 路径。

远程会话 chrome、渲染、输入、协议、FFI 与 native 安全存储实现不属于本改动。页面返回逻辑保持既有行为。

## 验证与验收

源审查核对当前 DevEco SDK 的 `SelectOption`、Select 字体/菜单宽度、ButtonStyleMode、HitTestMode、AccessibilityRoleType.CHECKBOX 和 checked 属性，避免猜测组件 API；`git diff --check` 只证明文本差异无空白问题。

主代理负责隔离 Hvigor 编译、签名、安装和实际手机/PC 截图验证。要求分别确认普通竖屏全部登录信息可见、键盘出现后字段可达、横屏/大字可滚动、明暗外观、原生焦点/键盘按钮激活、标签/状态可访问、最近连接恢复、确认登录页无开发验证入口。编译、截图、生命周期/交互和真实远程互通是不同证据层，不得互相替代。

实施阶段不伪造镜像布局的单元测试，也不从估算高度声称设备验收已经完成。最终实测与剩余限制由主代理在该变化的 README 矩阵和验证证据中记录。

## 2026-10-16：选择器随字号换行修正

普通双协议包的八格实际外观检查发现：模式选择加入后，目标、模式、端口仍共享同一行；标准竖屏系统名、大字竖屏系统与模式名、大字横屏系统名发生省略。该缺陷阻止登录外观验收。沿用上述一表单、原生控件、持久标签和字号/触摸目标要求，手机将六字段置于同一现有 Flex，原生宽度随字体缩放并自然换行，不新增字号状态或监听。

本节取代手机“目标系统与端口同排”的固定排布描述。窄手机有模式时目标占满一行，模式与端口在足够宽度时同排；没有模式时目标与端口可同排。宽手机各字段平铺，不再把前三项塞入半宽单元。采用原生 fp 宽度、maxWidth100%、禁止压缩和12vp换行间距；初始200fp字段/96fp窄屏端口只是需实包确认的候选，不承诺固定列数。普通字号仍需实际确认全部基本表单同页，大字号允许滚动，不以缩字、截断选择值或隐藏字段达标。

PC 保留原有嵌套行、数值和事件语义。手机地址、用户名、密码仍是同一父 Flex 下的固定声明；密码 ForEach 与唯一安全输入框不随方向/字号重建，提交、协议、端口、凭据和会话流程保持。该修正遵循同一 Material 3/HIG 自适应与大字可读要求，无设计例外。源码/编译不能替代新包八格像素、滚动、控件可达和后续凭据交互验收；PC 等用户结束手工填写后另行验证。

2026-10-16实包补充：已载入密码时，宽手机的全行安全存储提示会挤出底部按钮。仅在宽手机，将原14fp同文提示放到密码标签旁的原生可换行Flex中；窄手机与PC仍用原全行提示。提示持续可见，不裁字、不缩字体，也不隐藏错误。密码Column/ForEach父级与输入回调保持，普通字号是否同页仍以新包实测决定。

2026-10-16就地提示的原生测量对照：嵌套可换行Flex在实包稳定状态仍使外层字段区额外预留57px。下一候选复用原fieldLabel的单Text，按宽手机已载入条件合并密码标签与同文状态；自然文本换行、14fp和其它路径不变，避免额外容器。此为需新包对照验证的测量假设，不声称已定位系统内部算法；若失败继续保留实测差异，不从源码计算宣布一屏通过。

2026-10-16更新路径与测量边界：单Text候选在竖屏载入安全凭据后旋转横屏，外层字段区534px且按钮进入视口，但持久状态文字消失；稳定探测与原图相同。因此该候选不是等内容测量对照，不能认定57px问题已解决。下一对照必须让原生Text自身读取宽手机和credentialLoaded条件，避免经字符串值参数捕获初始标签；仍单Text、14fp、自然换行、固定密码父路径与原事件。只有完整提示持续可见后才能重新判断测量；若裁切恢复，应调整原生字段测量架构，不补偿高度或删除状态。

2026-10-16确定字段测量宽度：直接动态Text候选已在实包恢复完整状态，但横屏字段区仍591px、按钮超视口45px。下一候选仅宽手机六字段保留原生width字符串200fp，增加minWidth=calc(33.333333% - 12vp)、maxWidth=100%，取消grow二次扩宽；SDK约束为max(百分比槽,min(可用宽,原生200fp))。标准字号优先保持旧约805px最终列宽，大字按原生fp撑宽自然换行，超过整行宽度时封顶100%；不新增字体状态或测量，不强制三列，末侧可保留约12vp横向余量。窄手机、PC、密码父路径和事件保持。此为需新包验证的测量架构候选，不认定系统内部首轮测量/缓存根因，也不从公式宣布一页通过。

2026-10-16本轮有限实包验收：上述确定宽度方案的源码与正式BOTH包已通过独立审查。手机八种标准/特大、浅/深、横/竖状态均实际截屏；普通表单同页，大字四格真实滚动到按钮并返回，Windows/RDP和完整持久载入提示可读。接受范围仅为该API26手机包的外观/滚动，不推导引擎内部测量根因、任意布局路径相同几何或密码/键盘行为。一次新包登录停在网络连接，认证未开始；完整交互、PC和真实互通继续按原验收要求执行，详见[验证记录](../../validation/harmony-login-layout-20261013.md)。
