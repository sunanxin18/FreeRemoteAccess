# H.264 luma DC ARM64 数值内核验证

日期：2026-10-13。此记录仅覆盖固定 FFmpeg 8.1.2 的一个 H.264 8-bit luma DC 变换/反量化函数，不代表完整 H.264、RDP AVC444 或鸿蒙生产客户端通过。系统 AVCodec 优先策略保持；当前模拟器的系统输出阻塞另见[系统验证](harmony-system-codec-20261013.md)。

## 源码与行为

`93e0a6b` 新增固定源补丁，生产差异仅为 `libavcodec/aarch64/h264idct_neon.S` 和 `libavcodec/aarch64/h264dsp_init_aarch64.c`。原 C oracle 未修改，现有 8-bit 且 NEON 可用的分支选择新函数；其他位深、架构和 callback 不变。当前补丁尚未进入生产 builder 或安装包。

- 原归档 SHA-256：`464beb5e7bf0c311e68b45ae2f04e9cc2af88851abb4082231742a74d97b524c`。
- 最终 patch SHA-256：`4527ec807869f2a8ae8c2843ce51c693f3cbb728104e4fb9e617627dec593c7c`。
- 新汇编 postimage：`b0debd265560c16110a0bfa0c2d92ceb283cf1fe967776ea00fad4274eb06cc4`。
- dispatch postimage：`54ed484b42d9c51e22dafa8d379c2f7e41a753d7bea28b10ed42229ebcf3d4c0`。

新核一次读完 16 个输入，先扩展到 signed32 再做两级 Hadamard；乘法和加128按32位回绕，随后算术右移8和非饱和窄化。仅写16个稀疏 DC halfword，其他240个输出系数保持。实际优化对象的新符号有69条指令/276 bytes，包含向量 `mul/add/sshr/xtn` 和16次稀疏 halfword store。新符号机器码 SHA-256 为 `1e70d378b34fb196afd0942b9bd0c31c1715b4042c6c3e8f032dad5e76b42476`。

## 本机执行

Apple M4、macOS26.6.2、Apple clang21.0.0，在新解压源码的私有静态测试构建执行。先观察实际原版 dispatcher 未选择新核的失败，再实施补丁；最终原 C、显式整数语义 oracle 和新 NEON 共 **5,974,518** 组数值/内存检查通过。包括合法 QP0–51 × scaling1–255、全幅基向量扫描、随机及舍入/回绕判别、输出对齐、输入输出重叠、保护页、输入只读、ABI保留寄存器和整个输出哨兵。

CPU关闭/开启 × 位深8/9/10/12/14 × chroma1/2/3 的30个实际 context通过；仅目标槽按条件改变。相同静态对象的上游 H264DSP checkasm 固定种子1280974886，30/30通过。全新归档重放 patch 的 postimage 与被测源码相同。
