# 鸿蒙普通客户端真实 Windows 会话

2026-10-15，状态 **实验性**。本轮手机模拟器通过普通应用连接授权Windows
原生RDP服务，实际显示桌面、保存并读取密码、以已保存凭据重连，并在横屏
点击远端开始按钮打开开始菜单。PC模拟器的真实登录尚未验证；Mac未接入。
这些结果不把默认关闭的构建模式提升为生产能力。

## 手机实际观察

用户确认Windows恢复后，宿主一次TCP3389探测在约0.104秒成功；随后才进入
实际客户端流程。使用官方Emulator CLI操作既有专用phone API26 ARM64实例。
CUA无法绑定独立Emulator进程，沿用用户已授权的官方CLI途径。

账号和密码通过实际屏幕键盘点击输入，不把凭据字符串交给CLI参数或普通文件；
密码字段使用系统安全键盘。没有导出HUKS明文，也没有在协议中立状态快照写入
密码。选择“在此设备安全保存登录信息”。

| 项目 | 实际证据 |
|---|---|
| 原生服务认证与首帧 | 重连后应用状态为“已连接”，实际截图可见Windows PowerShell和任务栏 |
| 保存与读取 | 最近连接出现；选择该记录后显示“已从系统安全存储载入密码”，无需再次填写即可重连 |
| 后续画面 | 会话持续数分钟，任务栏时间更新，开始菜单变化可见；非具体编码或性能结论 |
| 横屏与触控 | 竖屏转横屏后保持会话/桌面，点击远端任务栏开始按钮后菜单打开 |
| 主动断开与再次重连 | 点击“断开”后返回表单，重新选择保存记录后无密码输入再次显示桌面 |
| 竖屏触控 | 再次重连后单次点击开始按钮，后续截图确认菜单打开 |
| 跨进程凭据 | 正常断开后停止/重启应用，PID从9768变为20428，选择保存记录显示HUKS载入提示，无密码输入再连接 |

最早一次提交在约4秒后回到表单，期间产生保存记录；该次退出根因未取得证据，
不能宣称修复或认定密码错误。使用已保存凭据的第二次会话持续数分钟，随后由
主代理主动断开。即时截图有时仍为操作前buffer；后续独立截图已确认菜单打开，
故没有据此修改或放宽输入门禁。只读审计也确认该次触控成功。

Hilog首轮误用互斥`-x/-z`参数，实际返回查询用法错误，无有效会话日志；修正
为`-x -P`后记录attach/resize及模拟器DGLES告警，没有可用于解释首轮退出的
会话错误。日志在内存中过滤凭据/输入文本字段后保存，没有清空日志、改变权限
或修改系统配置。告警本身不能当作本次退出或输入故障的根因。

## PC与剩余验收

PC首次屏幕键盘触发系统“小艺输入法”隐私协议，由用户本人完成基本模式选择。
没有代为接受协议或授予通讯录/麦克风权限。随后普通用户名字段通过系统虚拟
键盘点击输入；主机地址和安全保存选项已准备，但密码框没有显示可点击的虚拟
键盘，尚未输入密码或发起认证。只读查看系统键盘设置后已关闭，没有修改设置。
官方Emulator的fill命令会把文本放入进程参数，因此没有用它注入密码；已请用户
只手动填写密码，后续再由主代理验证登录。PC真实认证与桌面仍未验证。

本轮后续探测TCP3389约0.016秒成功，12:09手机截图仍显示实际Windows桌面及
更新后的任务栏时间。为准备独立PC登录，12:15后主代理明确断开手机，随后确认
回到普通登录表单；不得把同一Windows账户的会话接管当成异常退出。

手机尚未完成真实远程键盘/IME、缩放后命中和完整前后台恢复；首次/换证完整
交互也未在本轮逐项验收。主页手势尝试没有观察到应用进入后台，不能算前后台测试通过。
PC保持独立验收；两端的Mac协议接线、真实会话与媒体继续开发。
