# Apple MVS ARM64 IDCT 计算基础

2026-10-15，状态为 **实验性**。新增默认关闭的
`frd-protocol-apple/mvs-native-idct-arm64`，只替换 MVS type-0 mode-5 和
type-1 scratch 共用的 8×8 IDCT。没有注册鸿蒙 Apple factory，也没有启用新的
生产解码选择。普通鸿蒙应用尚不能据此连接 Mac。

## 实现与默认行为

两列、两行分别使用 ARM64 NEON 双 lane i64 蝶形。保留原 13 位常量、两遍
11/18 位舍入、负数算术右移以及 Apple `value & 0x3ff` 范围表；没有替换成
32 位 libjpeg 运算或普通饱和裁剪。输入反量化可无损扩展为 i32，再用 widening
SIMD 乘法得到 i64。完整 i16 系数/u8 量化域的保守中间值上界为
129,589,009,110,171，小于 2^47。

原标量函数字节除名称外完全不变，作为默认路径和独立测试 oracle。
显式 feature 仅允许 ARM64，缺少 NEON 返回错误，不静默回退标量。
默认 Windows、macOS ARM64、Linux 选择不变；不新增 macOS Intel 支持。
协议解析、wire、缓存、generation、音频、颜色转换和 GUI 未改动。

当前 native 版本没有 DC 快捷路径。完整蝶形与原 DC 舍入代数等价，
但可能增加稀疏块成本；尚无速度收益或生产性能结论。最终 mask/table 映射
仍沿用原实现，不能把本项称为完整 MVS SIMD 解码器。

## 真实失败与修正

已知答案测试先用错误 stub 取得实际断言失败：DC -5 应为 127，stub 给出128。
初版 NEON intrinsics 的像素对照通过，但实际 OHOS 最终 ELF 中 LLVM 将部分
移加重新构造成48条标量乘法，静态检查明确失败。初版 ELF 与日志均保留。

修正只在常量乘法累加处使用寄存器 `ADD .2d` 内联汇编，声明向量输入/输出、
无内存/栈/标志副作用；不含手写调用栈或 ABI 探针。最终实际入口
`0x26ae90..0x26bce8` 共3672字节，包含206条 ADD .2d、27条 SUB .2d、
136条 SHL .2d、16条 SSHR .2d、8条 widening SMULL .2d；没有标量乘法
或直接/间接调用。主代理独立复现反汇编并核对相同字节，独立源码/数学/产物
审查 Spec PASS、Quality Approved。

## 目标产物与边界

最终 ELF 7,018,960 bytes，SHA-256：
`f9c7a6cb0ae0b61be5f84c3fc9a0b353f4d5b539b816b4466aba1b4a890234c3`。
它是官方 SDK 链接的 AArch64 PIE，解释器 `/lib/ld-musl-aarch64.so.1`，
直接依赖 `libc++_shared.so` 和 `libc.so`。FDK-AAC 沿用原有静态依赖。

官方 SDK AArch64 C++ 运行库1,262,504 bytes，SHA-256：
`f69947af100b652e349ae51e4a4888bcc7a327db9085272d318176ef1782bf0f`，
SONAME 为 `libc++_shared.so`，其额外依赖只有 `libc.so`。SDK link-time libc
身份不等于设备 libc 身份。未修改系统库或 HAP native 允许清单。

同一 ELF 和官方 C++ 库已按手机、PC 顺序在两台专用 API26 模拟器执行。
仅在任务目录暂存，逐命令设置 `LD_LIBRARY_PATH`，没有安装系统库或修改应用。
两端上传后和测试后的 guest hash，以及主机输入前后 hash 均匹配上述身份。

这仍是 CLI ELF 计算/消费者测试，不是应用沙盒、HAP、音频或远程会话验证。
